# Словарь данных

Документ описывает очищенный набор `data/processed/complaints_clean.pkl`, который создаётся в `03_data_cleaning.ipynb` и используется для исследовательского анализа.

## Уровень данных

- Одна строка соответствует одной жалобе CFPB.
- Количество строк: 141 822.
- Количество столбцов: 21.
- Периоды: январь–март 2024 года и январь–март 2025 года.
- Продукты: кредитные карты, расчётные и сберегательные счета, денежные переводы и платёжные сервисы.
- `complaint_id` заполнен и уникален для каждой строки.

## Основные категориальные значения

### `product`

- `Credit card`;
- `Checking or savings account`;
- `Money transfer, virtual currency, or money service`.

### `submitted_via`

- `Web`;
- `Phone`;
- `Referral`;
- `Postal mail`.

### `company_response`

- `Closed with explanation`;
- `Closed with non-monetary relief`;
- `Closed with monetary relief`;
- `Untimely response`.

### `timely_response` и `is_timely`

| `timely_response` | `is_timely` | Значение |
|---|---:|---|
| `Yes` | `True` | Компания ответила в установленный срок |
| `No` | `False` | Компания не ответила в установленный срок |

`company_response` и `timely_response` описывают разные признаки и не должны использоваться как взаимозаменяемые поля.

## Производные признаки

### `source_file`

Используется для контроля происхождения строк и проверки соответствия содержимого ежемесячного файла указанному в его названии периоду.

### `year`, `month`, `year_month`

Созданы на основе `date_received`. Они используются для сравнения первого квартала 2024 и 2025 годов и для помесячной динамики.

### `is_timely`

Создан для расчёта количества и доли своевременных ответов без неявного преобразования строк `Yes` и `No`.

### `hours_to_send`

Рассчитывается по формуле:

```python
(
    date_sent_to_company
    - date_received
).dt.total_seconds() / 3_600
```

Значение может быть дробным: например, `0.25` часа соответствует 15 минутам.

Этот показатель характеризует скорость маршрутизации жалобы от CFPB к компании. Он не является продолжительностью ответа компании, потому что дата фактического ответа отсутствует.

## Принятые решения по качеству данных

- Строки не удаляются без обоснованной причины.
- Единственная жалоба без `issue` сохраняется в общей таблице, но исключается из анализа проблем.
- Пропуски в `sub_issue`, `company_public_response` и `tags` считаются ожидаемыми и не заполняются искусственно.
- Строки без `state` сохраняются, но не используются в географическом анализе.
- Дубликаты `complaint_id` отсутствуют.
- Отрицательные значения `hours_to_send` отсутствуют.
- Исходный `timely_response` сохраняется для контроля, а для вычислений используется `is_timely`.

## Ограничения интерпретации

- `state` относится к потребителю, а не к местонахождению компании.
- Количество жалоб по компаниям нельзя сравнивать как показатель качества без данных о размере клиентской базы и рыночной доле.
- Количество жалоб по штатам нельзя трактовать как региональный уровень риска без нормализации на население.
- Набор содержит только выбранные продукты и первый квартал двух лет, поэтому выводы нельзя переносить на весь рынок или полный календарный год.
