# Financial Complaints Analysis

Аналитический проект по данным [Consumer Complaint Database](https://www.consumerfinance.gov/data-research/consumer-complaints/) Бюро финансовой защиты потребителей США (CFPB).

Проект исследует, почему количество жалоб в первом квартале 2025 года заметно отличается от первого квартала 2024 года и сопровождался ли рост нагрузки изменением операционных показателей обработки жалоб.

## Данные

В анализ включены 141 822 жалобы за два сопоставимых периода:

- 1 января — 31 марта 2024 года;
- 1 января — 31 марта 2025 года.

Рассматриваются три продуктовые категории:

- `Credit card`;
- `Checking or savings account`;
- `Money transfer, virtual currency, or money service`.

Исходные данные представлены шестью ежемесячными CSV-файлами. Они не хранятся в Git из-за размера и должны находиться локально в `data/CFPB_data/`:

```text
complaints-2024-01.csv
complaints-2024-02.csv
complaints-2024-03.csv
complaints-2025-01.csv
complaints-2025-02.csv
complaints-2025-03.csv
```

Подробное описание подготовленной таблицы находится в [`docs/data_dictionary.md`](docs/data_dictionary.md).

## Аналитические вопросы

1. Как изменилось количество жалоб между первым кварталом 2024 и первым кварталом 2025 года?
2. Как изменилась структура жалоб по продуктам?
3. Как изменилась структура проблем внутри каждого продукта?
4. Какова доля своевременных ответов компаний?
5. Какие компании и регионы выделяются в данных?
6. Как распределено время передачи жалобы от CFPB компании?
7. Чем объясняется необычный объём жалоб в январе 2025 года?

Анализ строится от общей динамики к последовательному сужению: продукт → проблема → компания и регион → отдельный период.

## Ключевые этапы проекта

| Ноутбук | Назначение |
|---|---|
| `01_data_initialization.ipynb` | Загрузка шести CSV-файлов, проверка схемы, объединение, преобразование дат и создание временных признаков |
| `02_data_quality.ipynb` | Проверка пропусков, уникальности идентификаторов, категориальных значений и логической согласованности дат |
| `03_data_cleaning.ipynb` | Переименование полей в `snake_case`, создание `is_timely` и расчёт `hours_to_send` |
| `04_eda.ipynb` | SQL-агрегации, исследовательский анализ и визуализация результатов |

Промежуточные файлы сохраняются локально в `data/processed/` и исключены из Git.

## Порядок запуска

1. Скачать отфильтрованные данные из Consumer Complaint Database и сохранить шесть файлов с указанными выше именами в `data/CFPB_data/`.
2. Установить необходимые библиотеки:

   ```bash
   python -m pip install pandas duckdb matplotlib seaborn jupyter
   ```

3. Последовательно выполнить ноутбуки `01` → `02` → `03` → `04`.
4. Перед полным выполнением каждого ноутбука перезапустить его ядро, чтобы результаты не зависели от переменных, оставшихся в памяти от предыдущих запусков.

## Ограничения

- Consumer Complaint Database не является статистически репрезентативной выборкой всех клиентов финансовых организаций.
- Количество жалоб нельзя напрямую интерпретировать как качество компании или продукта без информации о клиентской базе, количестве операций и рыночной доле.
- Сравнение штатов без нормализации на население показывает концентрацию записей, но не уровень риска для жителя региона.
- `hours_to_send` отражает время между получением жалобы CFPB и её передачей компании, а не скорость ответа компании.
- Поле `is_timely` показывает только факт соблюдения срока ответа; дата фактического ответа компании в наборе отсутствует.
- Выводы относятся только к первому кварталу 2024 и 2025 годов и к трём выбранным продуктам.
